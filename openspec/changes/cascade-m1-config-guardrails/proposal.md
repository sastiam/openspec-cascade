# Proposal: Milestone M1 — Centralized Configuration, Zod Schemas, Guardrails & Strict Code Hygiene

## Why

`openspec-cascade` currently relies on a monolithic `config.ts` with unvalidated numeric/boolean parsing, silent CLI flag swallowing (`strict: false`), drifting `*_CONSTANTS` definitions across `src/` modules, import-time `loadConfig()` side effects in `cascade.ts`, hardcoded Bun/Nuxt/Drizzle verify assumptions, missing secret redaction and strict budget/branch guardrails, and disabled `@typescript-eslint/no-explicit-any` enforcement allowing `any` leaks.

Milestone M1 establishes the foundational `src/config/` hexagonal layer (Features F01–F05) so every downstream milestone (M2–M6) builds on immutable centralized constants, fail-closed Zod boundary validation, AWS Well-Architected guardrails, dynamic stack-aware config loading, and strict TypeScript/ESLint hygiene.

## What Changes

1. **F01 (`src/config/constants.ts`)**: Introduce strongly-typed immutable `as const` constant namespaces (`RUNTIME_CONSTANTS`, `ENGINE_CONSTANTS`, `BUDGET_CONSTANTS`, `TIMEOUT_CONSTANTS`, `GIT_CONSTANTS`, `SDD_CONSTANTS`, `DIAGRAM_CONSTANTS`, `EXIT_CODE_CONSTANTS`, `FORMAT_CONSTANTS`, `GREPTILE_CONSTANTS`, `TELEMETRY_CONSTANTS`, `GUARDRAIL_CONSTANTS`, `VERIFY_CONSTANTS`). Reconcile drifting constants in `src/` (`RATE_LIMIT_SLEEP_MS`, default models, truncation bounds, exit codes) and compose `CONSTANTS` in `config.ts` for 100% backward compatibility.
2. **F02 (`src/config/schemas.ts`)**: Add `zod` dependency and define strict finite-number/boolean preprocessors (rejecting `NaN`, `Infinity`, empty strings, negative budgets/timeouts, out-of-range or non-integer `usageLimitPercent`/`tokenWatermarkPercent` percentages, with domain-scoped minimum constants `TIMEOUT_CONSTANTS.MIN_DURATION_MS`, `SDD_CONSTANTS.MIN_REVIEW_DURATION_SECONDS`, `GUARDRAIL_CONSTANTS.MIN_POSITIVE_INT`) plus domain Zod schemas (`RuntimeConfigSchema`, `EngineConfigSchema`, `GateBudgetsSchema`, `SddConfigSchema`, `GreptileConfigSchema`, `TelemetryConfigSchema`, `DiagramsConfigSchema`, `CascadeFileConfigSchema`, `CascadeConfigSchema`) and `ConfigValidationError` (exit code `2`).
3. **F03 (`src/config/guardrails.ts`)**: Implement `enforceSessionBudget` (`BudgetExceededError`, fail-closed on `NaN`/non-finite/non-positive/strict `>=`), `redactSensitiveData` (`WeakSet` circular-ref `[Circular]`, bounded `maxDepth`, container preservation for `Array`, `Map`, `Set`, `Date`, `RegExp`, `Error`, plain/`null`-prototype objects, prototype-safe `"__proto__"` own-property handling via `Object.defineProperty`, and key/token/PEM/URL-credential redaction), and `evaluateProtectedBranchGuard` (`ProtectedBranchError`, blocking non-dry-run on `main`/`master`/`stable` while allowing `--dry-run` preview with a warning).
4. **F04 (`src/config/loader.ts`, `src/config/index.ts`, `config.ts`, `platform.ts`, `cascade.ts`)**: Implement strict `parseCliArgs` (`strict: true`, fail-closed, adding `--budget`/`--max-budget`, `--total-budget`, `--usage-limit`, `--max-turns`, `--max-attempts`, `--mode`, `--config`), synchronous `.openspec-cascade.json` loader, layered precedence (`overrides > CLI args > CASCADE_* env > .openspec-cascade.json > dynamic/repo defaults`, including strict `logDir` precedence `overrides.logDir > --log-dir > CASCADE_LOG_DIR > fileConfig.logDir > default`, non-blank `CASCADE_CHANGES` fallback, and fail-closed rejection of empty `--repo ""`, `CASCADE_REPO=""`, `overrides.repo: ""`, `--log-dir ""`, and `overrides.logDir: ""` before path normalization or file-config loading), dual `loadConfig` signatures, `hasLockfile`/`tryDetectPackageManager` stack detection in `platform.ts`, and lazy CLI config loading in `cascade.ts` (removing import-time `loadConfig()`, wiring guardrails and exit code `2`).
5. **F05 (Strict TypeScript, ESLint & Clean Code)**: Enable `"@typescript-eslint/no-explicit-any": "error"` and ignore `".agents/**"` in `eslint.config.js`, eliminate all 15 AST `any` leaks across the repository, expand `lint.test.ts` to cover `src/**/*.ts`, enforce zero inline function-body comments in all M1-created/modified files, and verify with real unit/integration tests.

## Definition of Done

- `bunx openspec validate cascade-m1-config-guardrails --strict` exits `0`.
- `bun test`, `bun run typecheck`, and `bun run lint` all exit `0` with zero failures, zero TypeScript errors, and zero ESLint errors/warnings.
- CLI fail-closed smoke checks (`--engine invalid`, `--unknown-flag`, `--budget -5`, `--budget abc`) exit with code `2`, and `--help` exits `0`.
- All tasks in `tasks.md` are checked off `[x]`.
